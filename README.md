# פלטפורמת הלמידה של NGG

מערכת LMS פעילה — צד לומד וצד ניהול — הבנויה סביב שתי יחידות הלמידה המופקות של NGG,
עם קריינות, כתוביות ואנימציות המסונכרנות על ציר זמן אחד.

התוכן, שפת העיצוב וארכיטקטורת המסכים נגזרו מקובצי העיצוב שבתיקייה `design/`, שנשמרו כפי שהם.

---

## מה מומלץ: Vercel

**ההמלצה היא לפרוס על Vercel.** שלוש סיבות מהותיות, לפי סדר החשיבות:

1. **הגנת גישה.** GitHub Pages מגיש כל אתר לאינטרנט הפתוח, ללא אפשרות להגביל גישה. תוכן הדרכה
   של NGG וללקוחותיה, ובוודאי נתוני התקדמות של לומדים בשם מלא, אינם אמורים להיות פומביים.
   ב-Vercel אפשר להפעיל Deployment Protection או SSO ארגוני ולסגור את הפריסה לצוות ולארגון בלבד.
2. **שמירת נתונים אמיתית.** לצד הניהול יש משמעות רק אם התוכניות והמעקב נשמרים ומשותפים בין
   משתמשים. ב-Vercel יש שכבת API (`/api`) שנשענת על Vercel KV. ב-GitHub Pages אין שרת כלל,
   ולכן כל נתון נשמר בדפדפן של המשתמש בלבד ואינו משותף.
3. **קבצי אודיו כבדים.** כ-38MB קריינות מוגשים דרך ה-CDN של Vercel עם Range Requests ו-Cache
   headers שכבר מוגדרים ב-`vercel.json`.

**GitHub Pages נתמך ועובד** — אותו build רץ בשתי הסביבות ללא ענף קוד נפרד — אבל מתאים להדגמה
פנימית או תצוגה ללקוח, לא להפעלה עם נתוני לומדים.

| | Vercel | GitHub Pages |
|---|---|---|
| הגבלת גישה | Deployment Protection / SSO | אין — פומבי תמיד |
| שמירת נתוני ניהול והתקדמות | Vercel KV, משותף | דפדפן המשתמש בלבד |
| שכבת API (`/api`) | פעילה | לא קיימת |
| ניתוב | Hash routing (עובד בשתיהן) | Hash routing |

## מסלול הדגמה

מרחב עבודה חדש נטען עם 5 תוכניות, 8 לומדים והתקדמות לדוגמה, כך שכל מסך מלא מהרגע הראשון.
נתוני ההדגמה מסומנים ככאלה במסכי הלומדים וההגדרות, וכתובות הדוא״ל בדומיין השמור `.invalid`.

**כניסה:** שם + דוא״ל, ובוחרים "מנהל תוכן" או "לומד". מנהל יכול לעבור בין הצדדים מהמתג בכותרת.

### צד הניהול

| מסך | מה להראות |
|---|---|
| סקירה | 2 תוכניות פעילות, 8 לומדים, 55% התקדמות ממוצעת, התראת התוכן החסר |
| תוכניות | 5 תוכניות בארבעה סטטוסים, סינון וחיפוש |
| בנאי תוכניות | 4 שלבים · סינון "מופק בלבד" · גרירה לסידור · צ'קליסט פרסום · קישור ללומדים |
| דשבורד תוכנית | התקדמות לפי יחידה, רשימת משתתפים, יחידות בהפקה מסומנות |
| ספריית תוכן | 16 יחידות, סינון לפי תפקיד/נושא/סוג, דף יחידה עם בוחן ומטלה |
| אנליטיקה | התקדמות לפי תוכנית + נשירה לפי יחידה |
| הגדרות | מצב אחסון, מצב התוכן לכל מקטע, ואיפוס לנתוני הדגמה בין הרצות |

### צד הלומד

**להדגים את יחידה 02 — "לעבוד עם AI בצורה בטוחה ואחראית".** חמישה מתוך חמישה נאגטים עם
קריינות מלאה, 16 דקות תוכן.

1. מסלול הלמידה → כרטיס "להמשיך מאיפה שעצרת"
2. דף התוכנית → 6 יחידות, מהן 4 מסומנות "בהכנה"
3. דף היחידה → מטרת למידה, מבנה, ומה הלומד יוכל בסיום
4. הנגן → קריינות + כתוביות + אנימציה מסונכרנות; מעבר בין נאגטים מהרשימה בצד; 5 קצבי השמעה; תמלול לחיץ
5. סוף נאגט → "עצור וחשוב" → תרגיל עם בדיקה וניקוד → מקטע הבא

**מה לא להדגים:** נאגטים 2–4 ביחידה 01. חסר להם קובץ הקריינות (ראו "מצב התוכן"), והם רצים
ללא קול. נאגטים 1 ו-5 ביחידה 01 כן מוקראים במלואם.

התוכנית הראשית פתוחה לפי סדר חופשי, ו"יסודות למנהלים — מחזור 2" סדרתית — כדי שאפשר להדגים
את שני מודלי ההשלמה.

### בדיקה לפני פרזנטציה

```bash
npm run build && npm run preview       # בטרמינל אחד
npm i --no-save playwright
node scripts/verify-nuggets.mjs      http://127.0.0.1:4173/   # 10 הנאגטים
node scripts/verify-walkthrough.mjs  http://127.0.0.1:4173/   # שני הצדדים
```

`verify-nuggets` בודק לכל נאגט שהקובץ הנכון נטען, שראש ההשמעה נמצא בתוך הפרוסה של אותו
נאגט (קריטי — ארבעה נאגטים ביחידה 02 חולקים קובץ אחד באורך 12 דקות), שהכתובית והסצנה
מתקדמות, ושההשמעה נעצרת בגבול הנאגט. `verify-walkthrough` עובר על שני הצדדים ומצלם כל מסך.

## פריסה

### Vercel (מומלץ)

```bash
# מהריפו, פעם אחת
vercel link
vercel --prod
```

Vercel מזהה את הפרויקט לפי `vercel.json` (framework: vite, build: `npm run build`, output: `dist`)
ומפרסם אוטומטית את הפונקציות שב-`api/`.

**להפעלת שמירת נתונים קבועה** — יוצרים Vercel KV (או Upstash Redis) ומגדירים בפרויקט:

```
KV_REST_API_URL=...
KV_REST_API_TOKEN=...
```

בלי המשתנים האלה ה-API עדיין עונה, אך שומר בזיכרון בלבד. מרחב העבודה מציג את המצב במפורש
תחת **הגדרות → אחסון נתונים**, כדי שלא יונח שיש עמידות שאין.

**להגבלת גישה** — Vercel → Project → Settings → Deployment Protection.

### GitHub Pages

הוורקפלואו `.github/workflows/pages.yml` בונה עם `DEPLOY_TARGET=pages` ו-`PAGES_BASE=/<repo>/`
ומפרסם. הוא **מופעל ידנית בלבד** (workflow_dispatch), ובכוונה: Pages מגיש לאינטרנט הפתוח בלי
אפשרות להגביל גישה, ולכן פרסום תוכן ההדרכה שם צריך להיות החלטה מפורשת ולא תוצאת לוואי של מיזוג.

להפעלה: הגדרות הריפו → Pages → מקור **GitHub Actions**, ואז הרצת הוורקפלואו מלשונית Actions.

```

  player/       מנוע הנגן: ציר זמן, שעון, סצנות, כתוביות, תרגילים
  learner/      צד הלומד
  admin/        צד הניהול
  state/        מרחב העבודה, זהות, התמדה
  app/          שלד, ניתוב, חישובי התקדמות

```

### סנכרון קריינות · כתוביות · אנימציה

זה הלב של המערכת, ולכן שלושת הערוצים קוראים **שעון אחד**:

- `src/player/timeline.ts` הופך את נתוני היחידה לרשימת כתוביות עם `t0`/`t1` על ציר הזמן של
  המקטע. כשהתמלול הגיע עם חותמות זמן (`timed`) הבלוקים מעוגנים כלשונם — אחרי החלת `tcBase`
  ו-`tcRate` — והשורות בתוך כל בלוק נפרסות לפי משקל דיבור. בהיעדר חותמות, הפריסה היא לפי
  משקל על פני המקטע.
- `src/player/useTimelineClock.ts` הוא מקור האמת היחיד לזמן. כשיש קריינות, כל פריים קורא
  `audio.currentTime` — ולכן כתובית לא יכולה להקדים את הקול. כשאין קובץ קריינות, אותה לולאה
  רצה על `performance.now()` באותו קצב, כך שהכתוביות והאנימציה עדיין רצות מסונכרנות זו לזו
  והמקטע נשאר ניתן ללמידה.
- `src/player/Stage.tsx` מרנדר את הסצנה. מעבר בין סצנות מבצע remount, ולכן אנימציות הכניסה
  ב-CSS נורות בדיוק ברגע שהקריינות מגיעה לסצנה — זה מה שקושר את התנועה לקול.

## מצב התוכן — הערה חשובה

שתי היחידות מוטמעות במלואן: 10 מקטעים, 527 שורות כתוביות, 106 סצנות ו-10 תרגילים — כ-28 דקות תוכן.

**חסר קובץ קריינות אחד:** `assets/audio/u1-n2.mp3`. הקובץ שהגיע עם הריפו היה placeholder של
2 בתים ולא קובץ אודיו, ולכן הוסר. הוא נדרש לשלושת המקטעים 2–4 ביחידה 01 (0–431 שניות).

עד שיתווסף, המקטעים האלה פועלים במצב ללא קריינות: הכתוביות והאנימציה רצות ומסונכרנות זו לזו,
הנגן מציג זאת במפורש ללומד, וצד הניהול מציג את החוסר ב**הגדרות → מצב התוכן**.

להשלמה:

```bash
cp <u1-n2.mp3> public/assets/audio/u1-n2.mp3
npm run scan:audio
```

הכתוביות והתזמונים כבר מוגדרים ויסתנכרנו אוטומטית — אין צורך בשינוי קוד.

`u1-full.mp3` נמצא בספרייה אך אינו מקושר לאף מקטע (177 שניות, קצר מכדי לכסות את 2–4).

## אבטחה והרשאות

מסך ההזדהות באפליקציה **מזהה** משתמש לצורך מעקב התקדמות והפרדה בין צד הלומד לצד הניהול.
הוא **אינו מאמת** אותו: אין סיסמה ואין בדיקה בצד השרת, וכך גם קוד הגישה שבקישור לתוכנית.

לפני הכנסת נתוני לומדים אמיתיים יש להגן על הפריסה עצמה — Deployment Protection של Vercel או
SSO ארגוני (Entra ID) — ולחבר את הזהות ממנו. עד אז יש להתייחס לפריסה כאל סביבת הדגמה.

נקודות נוספות שכבר מטופלות: כותרות `X-Robots-Tag: noindex` ו-`X-Content-Type-Options` מוגדרות
ב-`vercel.json`; נקודת ה-API מקבלת שני סוגי מפתחות בלבד ואינה משמשת כ-KV proxy כללי; תוכניות
מועברות לארכיון ואינן נמחקות, כדי לשמור על היסטוריית הלמידה.

## מודל הנתונים

- **יחידה** → חמישה **נאגטים**. לכל נאגט: פרוסת קריינות, כתוביות, סצנות, שאלת רפלקציה ותרגיל.
- **תוכנית** = לקוח, קהל יעד, רשימת יחידות מסודרת, מסרי פתיחה וסיום, תנאי השלמה וסטטוס.
- **התקדמות** נרשמת ברמת המקטע (נצפה / תורגל / ציון / נקודת עצירה), ומצטברת ליחידה ולתוכנית.

התקדמות מחושבת על יחידות מופקות בלבד. יחידות שעדיין בהפקה מסומנות "בהכנה" ואינן נספרות
במכנה — כדי שהאחוזים ישקפו תוכן שאפשר באמת להשלים. אחוז ההתקדמות בתוכנית משוקלל לפי נאגטים
ולא לפי יחידות, כך שלומד שנמצא בתוך יחידה לא מוצג כאפס.
