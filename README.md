# פלטפורמת הלמידה של NGG

מערכת LMS פעילה — צד לומד וצד ניהול — הבנויה סביב שתי יחידות הלמידה המופקות של NGG,
עם קריינות, כתוביות ואנימציות המסונכרנות על ציר זמן אחד.

התוכן, שפת העיצוב וארכיטקטורת המסכים נגזרו מקובצי העיצוב שבתיקייה `design/`, שנשמרו כפי שהם.
העיצוב הפעיל הוא `design/DESIGN-HANDOFF-v2.md` והפרוטוטייפ שלו,
`design/NGG Learning Platform Hi-Fi v2.dc.html`.

---

## מה מומלץ: Vercel

**ההמלצה היא לפרוס על Vercel.** שלוש סיבות מהותיות, לפי סדר החשיבות:

1. **הגנת גישה.** GitHub Pages מגיש כל אתר לאינטרנט הפתוח, ללא אפשרות להגביל גישה. תוכן הדרכה
   של NGG וללקוחותיה, ובוודאי נתוני התקדמות של לומדים בשם מלא, אינם אמורים להיות פומביים.
   ב-Vercel אפשר להפעיל Deployment Protection או SSO ארגוני ולסגור את הפריסה לצוות ולארגון בלבד.
2. **שמירת נתונים אמיתית.** לצד הניהול יש משמעות רק אם התוכניות והמעקב נשמרים ומשותפים בין
   משתמשים. ב-Vercel יש שכבת API (`/api`) שנשענת על Vercel KV. ב-GitHub Pages אין שרת כלל,
   ולכן כל נתון נשמר בדפדפן של המשתמש בלבד ואינו משותף.
3. **קבצי אודיו כבדים.** כ-38MB קריינות מוגשים דרך ה-CDN של Vercel עם Range Requests ו-Cache
   headers שכבר מוגדרים ב-`vercel.json`.

**GitHub Pages נתמך ועובד** — אותו build רץ בשתי הסביבות ללא ענף קוד נפרד — אבל מתאים להדגמה
פנימית או תצוגה ללקוח, לא להפעלה עם נתוני לומדים.

| | Vercel | GitHub Pages |
|---|---|---|
| הגבלת גישה | Deployment Protection / SSO | אין — פומבי תמיד |
| שמירת נתוני ניהול והתקדמות | Vercel KV, משותף | דפדפן המשתמש בלבד |
| שכבת API (`/api`) | פעילה | לא קיימת |
| ניתוב | Hash routing (עובד בשתיהן) | Hash routing |

## מסלול הדגמה

מרחב עבודה חדש נטען עם 7 תוכניות (4 בבעלות מאיה כהן, 3 של שאר הצוות), 449 לומדים ו-4
אבני דרך במחזורים — כך שכל מסך מלא מהרגע הראשון וכל המספרים מחושבים מרשומות אמיתיות:
141 פעילים בשבוע, 18 בסיכון, וציוני 91% / 68% לשתי היחידות המופקות.
נתוני ההדגמה מסומנים ככאלה במסכי הלומדים וההגדרות, וכתובות הדוא״ל בדומיין השמור `.invalid`.

**כניסה:** שם + דוא״ל, ובוחרים "מנהל תוכן" או "לומד". מנהל יכול לעבור בין הצדדים מהמתג בכותרת.

### צד הניהול

| מסך | מה להראות |
|---|---|
| דשבורד | ארבע אריחי דונאט, תוכניות מקובצות לפי לקוח, מתג שלי / של הצוות, גרף פעילות שבועי, יומן מחזורים, לומדים שנתקעו, כרטיס הספרייה הכהה |
| תוכניות | כרטיסי לקוח עם מונוגרמה, מתג שלי / של הצוות / הכול, חיפוש |
| בנאי תוכניות | 4 שלבים · סינון "מופק בלבד" · גרירה לסידור · צ'קליסט פרסום · קישור ללומדים |
| דשבורד תוכנית | התקדמות לפי יחידה, רשימת משתתפים, יחידות בהפקה מסומנות |
| ספריית תוכן | 16 יחידות, סינון לפי תפקיד/נושא/סוג, דף יחידה עם בוחן ומטלה |
| אנליטיקה | ארבעה אריחים, גרף מעורבות ל-12 שבועות, ציוני תרגילים לפי יחידה, טבלת לומדים בסיכון |
| הגדרות | מצב אחסון, מצב התוכן לכל מקטע, ואיפוס לנתוני הדגמה בין הרצות |

### צד הלומד

**להדגים את יחידה 02 — "לעבוד עם AI בצורה בטוחה ואחראית".** חמישה מתוך חמישה נאגטים עם
קריינות מלאה, 16 דקות תוכן.

1. מסלול הלמידה → הירו הכהה, מסר הפתיחה הפסטלי, ושורות המסלול עם מעגלי מצב
2. דף התוכנית → 6 יחידות, מהן 4 מסומנות "בהכנה"; שורה נעולה מציגה הודעה
3. דף היחידה → הפתיח כשורה ראשונה, מטרת למידה, מבנה, ומה הלומד יוכל בסיום
4. **מסך הפתיח** → "להתחיל — פתיח היחידה (1:34)" פותח אותו; נגן עם 28 פסי גל, פס
   התקדמות שנגזר מהאודיו האמיתי, ורשימת "מה בהמשך היחידה"
5. הנגן → קריינות + כתוביות + אנימציה מסונכרנות; מעבר בין נאגטים מהרשימה בצד; 5 קצבי השמעה; תמלול לחיץ
6. סוף נאגט → "עצור וחשוב" → תרגיל עם בדיקה וניקוד → מקטע הבא

שתי היחידות מוקראות במלואן — 10 מתוך 10 נאגטים, כ-28 דקות קריינות. אפשר להדגים כל מקטע.

התוכנית הראשית פתוחה לפי סדר חופשי, ו"יסודות למנהלים — מחזור 2" סדרתית — כדי שאפשר להדגים
את שני מודלי ההשלמה.

נאגט (קריטי — ארבעה נאגטים ביחידה 02 חולקים קובץ אחד באורך 12 דקות), שהכתובית והסצנה
מתקדמות, ושההשמעה נעצרת בגבול הנאגט. `verify-walkthrough` עובר על שני הצדדים ומצלם כל מסך.

## פריסה

### Vercel (מומלץ)

```bash
# מהריפו, פעם אחת
vercel link
vercel --prod
```

Vercel מזהה את הפרויקט לפי `vercel.json` (framework: vite, build: `npm run build`, output: `dist`)
ומפרסם אוטומטית את הפונקציות שב-`api/`.

**להפעלת שמירת נתונים קבועה** — יוצרים Vercel KV (או Upstash Redis) ומגדירים בפרויקט:

```
KV_REST_API_URL=...
KV_REST_API_TOKEN=...
```

בלי המשתנים האלה ה-API עדיין עונה, אך שומר בזיכרון בלבד. מרחב העבודה מציג את המצב במפורש
תחת **הגדרות → אחסון נתונים**, כדי שלא יונח שיש עמידות שאין.

**להגבלת גישה** — Vercel → Project → Settings → Deployment Protection.

### GitHub Pages

הוורקפלואו `.github/workflows/pages.yml` בונה עם `DEPLOY_TARGET=pages` ו-`PAGES_BASE=/<repo>/`
ומפרסם. הוא **מופעל ידנית בלבד** (workflow_dispatch), ובכוונה: Pages מגיש לאינטרנט הפתוח בלי
אפשרות להגביל גישה, ולכן פרסום תוכן ההדרכה שם צריך להיות החלטה מפורשת ולא תוצאת לוואי של מיזוג.

להפעלה: הגדרות הריפו → Pages → מקור **GitHub Actions**, ואז הרצת הוורקפלואו מלשונית Actions.

### מסך הפתיח

פתיח היחידה הוא שלב במסלול, לא כפתור צדדי: לחיצה על "להתחיל" מנתבת אליו כל עוד הלומד לא
שמע אותו והיחידה לא הושלמה, ואישור ממנו מסמן את הפתיח כנשמע ומוביל לנאגט הראשון שטרם נצפה.
הפרוטוטייפ מדמה את הנגן באנימציית CSS באורך 94 שניות; כאן הקריינות אמיתית, ולכן פס
ההתקדמות ותצוגת הזמן נגזרים משעון האודיו וכל יחידה מציגה את האורך שלה.

### מה מחושב ומה נתוני הדגמה

אחוזי ההשלמה, גדלי המחזורים, ציוני התרגילים לפי יחידה, ימי חוסר הפעילות ורשימת הלומדים
בסיכון — כולם מחושבים מרשומות ההתקדמות (`src/app/progress.ts`). מרחב העבודה שומר מצב נוכחי
ולא יומן אירועים, ולכן היסטוריה שבועית **אינה** ניתנת לגזירה ממנו: הסדרה בת 12 השבועות,
הפילוח היומי והזמן החציוני ליחידה יושבים ב-`src/content/demo-analytics.ts`, מסומנים כנתוני
הדגמה במסכים עצמם. להפוך אותם לאמיתיים נדרשת רשומת אירוע לכל השלמת נאגט.

### סנכרון קריינות · כתוביות · אנימציה

זה הלב של המערכת, ולכן שלושת הערוצים קוראים **שעון אחד**:

- `src/player/timeline.ts` הופך את נתוני היחידה לרשימת כתוביות עם `t0`/`t1` על ציר הזמן של
  המקטע. כשהתמלול הגיע עם חותמות זמן (`timed`) הבלוקים מעוגנים כלשונם — אחרי החלת `tcBase`
  ו-`tcRate` — והשורות בתוך כל בלוק נפרסות לפי משקל דיבור. בהיעדר חותמות, הפריסה היא לפי
  משקל על פני המקטע.
- `src/player/useTimelineClock.ts` הוא מקור האמת היחיד לזמן. כשיש קריינות, כל פריים קורא
  `audio.currentTime` — ולכן כתובית לא יכולה להקדים את הקול. כשאין קובץ קריינות, אותה לולאה
  רצה על `performance.now()` באותו קצב, כך שהכתוביות והאנימציה עדיין רצות מסונכרנות זו לזו
  והמקטע נשאר ניתן ללמידה.
- `src/player/Stage.tsx` מרנדר את הסצנה. מעבר בין סצנות מבצע remount, ולכן אנימציות הכניסה
  ב-CSS נורות בדיוק ברגע שהקריינות מגיעה לסצנה — זה מה שקושר את התנועה לקול.

## סרטוני הנאגטים (Remotion)

לכל נאגט יש גם גרסת וידאו מרונדרת ב-1920x1080: אותה קריינות, אותן כתוביות ואותן סצנות, אבל
מונפשות בכלים שהדפדפן לא נותן בזמן אמת. הקוד יושב ב-`remotion/`.

מה שחשוב בו: **הווידאו לא מתוזמן מחדש.** `remotion/lib/timing.ts` קורא ל-`buildTimeline`
מ-`src/player/timeline.ts` — אותו פותר כתוביות שהנגן באתר משתמש בו — וממיר שניות לפריימים.
לכן נאגט חותך באתר ובווידאו באותם רגעים בדיוק, ותיקון תזמון במקטע נכנס לשני המקומות בלי
לגעת באף קובץ אנימציה. אורך הקומפוזיציה נגזר מחלון הקריינות ולא נכתב ביד.

```bash
npm run video                                    # סטודיו: תצוגה מקדימה עם גרירה על ציר הזמן
npm run video:render                             # רינדור מלא
npx remotion still u01-n01 out/x.png --frame=830 # פריים בודד
```

- **דפדפן.** אם יש כרומיום מותקן על המכונה, הצביעו עליו ב-`REMOTION_BROWSER_EXECUTABLE`
  במקום לתת ל-Remotion להוריד אחד משלו.
- **גופנים.** תת-הקבוצות של Heebo מגורסאות ב-`public/assets/fonts` ונטענות
  ב-`remotion/fonts.ts`. רינדור לא יכול להסתמך על Google Fonts: הדפדפן חסר-הראש היה מתחרה
  ברשת ובמקרה של כישלון היה מקבע 4,700 פריימים בגופן חלופי בשקט. לרענון הגרסה:
  `node scripts/fetch-fonts.mjs`.
- **סצנות.** אחד-עשר מתוך שלושה-עשר סוגי הסצנות במודל התוכן ממומשים — כל מה שנאגטים 1
  ו-2 משתמשים בו (`type`, `chips`, `flow`, `negspace`, `mock`, `questions`, `principle`,
  `gauge`, `butlist`, `twoq`, `dial`). שני הנותרים (`quote`, `stairs`) מפילים את הרינדור
  בשגיאה מפורשת ולא נופלים לכרטיס טקסט גנרי: פלייסהולדר שמרנדר הוא פלייסהולדר שנשלח
  ללקוח, וכל נאגט אמור לקבל ויזואליזציה שנבנתה למה שהוא באמת אומר.
- **בימוי.** `remotion/art.ts` קובע על איזו שורת קריינות כל אלמנט בסצנה נתלה, לפי מפתח
  `<contentId>/<segmentId>.<sceneKey>`. קומפוננטת סצנה יודעת לצייר סוג של תמונה; היא לא
  יכולה לדעת איזו שורה בתסריט של נאגט מסוים מזכירה איזה אלמנט — זו קריאה של הטקסט, וזה
  ההבדל בין חשיפה שנוחתת על המילה לחשיפה שקורית בסביבתה. נאגט 2 הבהיר את הנקודה: `chips`
  נפתח בנאגט 1 על סריג טוקנים כי הקריינות שם עוסקת באופן שבו המודל מייצר תשובות, ואותו
  סריג מעל רשימת החוזקות של נאגט 2 היה קישוט. שוט בלי רשומה נופל לברירת מחדל שפורסת את
  האלמנטים על פני הקיוז שלו — תמיד סביר, לרוב פחות מדויק.
- **עלות רינדור.** אין GPU בקונטיינר, ולכן הרסטריזציה תוכנתית: נאגט של שתי דקות וחצי לוקח
  כ-45 דקות על ארבעה ליבות. לסבב עיצוב עובדים עם `remotion still` ולא עם רינדור מלא.

**מצב:** `u01-n01` ו-`u01-n02` הופקו. שאר הנאגטים נבנים אחד-אחד — כל אחד הוא רשומה נוספת
במערך `NUGGETS` ב-`remotion/Root.tsx`, בתוספת סוגי הסצנות שהוא מציג ורשומת בימוי
ב-`art.ts`.

## מצב התוכן

שתי היחידות מוטמעות במלואן: 10 מקטעים, 527 שורות כתוביות, 106 סצנות ו-10 תרגילים — כ-28 דקות תוכן.

הקריינות היא קובץ אחד לכל נאגט, `u1-n<N>.mp3` / `u2-*.mp3`, וכל מקטע מתחיל מהשנייה הראשונה
בקובץ שלו (למעט `u1-n1.mp3`, שמכיל גם את פתיח היחידה לפני נאגט 1).

**כל עשרת הנאגטים מוקראים במלואם.** אין חוסרי תוכן.

להחלפת קובץ קריינות:

```bash
cp <u1-nX.mp3> public/assets/audio/
npm run scan:audio
```

`scan:audio` מדפיס את האורך בפועל; אם הוא שונה מה-`end` שרשום ב-`src/content/unit-01.ts`
יש לעדכן אותו. במקטע שנפתח בכותרת מוקראת (נאגטים 4 ו-5 ביחידה 01) יש גם `body` שמסמן
מתי הכותרת נגמרת — הוא על אותו ציר זמן כמו `start`, ולכן החלפת קובץ עם אורך פתיח שונה
מחייבת לעדכן גם אותו.

### כותרות אורך שגויות בקבצים חתוכים

נאגט שנחתך מהקלטת מאסטר ארוכה שומר לעיתים את כותרת ה-Xing/Info של המאסטר. הדפדפן סומך על
הכותרת הזאת גם לאורך וגם למיקום בגלילה — כך שקובץ באורך 149 שניות שהכותרת שלו טוענת 431
יגרום לכל גלילה לנחות במקום הלא נכון. זה קרה בפועל בקובץ של נאגט 2 והכותרת הוסרה.

`npm run scan:audio` בודק את זה בכל הרצה ונכשל עם הסבר אם הפער גדול משנייה.

`u1-full.mp3` נמצא בספרייה אך אינו מקושר לאף מקטע (177 שניות) — כנראה שריד מהפקה מוקדמת.

## אבטחה והרשאות

מסך ההזדהות באפליקציה **מזהה** משתמש לצורך מעקב התקדמות והפרדה בין צד הלומד לצד הניהול.
הוא **אינו מאמת** אותו: אין סיסמה ואין בדיקה בצד השרת, וכך גם קוד הגישה שבקישור לתוכנית.

לפני הכנסת נתוני לומדים אמיתיים יש להגן על הפריסה עצמה — Deployment Protection של Vercel או
SSO ארגוני (Entra ID) — ולחבר את הזהות ממנו. עד אז יש להתייחס לפריסה כאל סביבת הדגמה.

נקודות נוספות שכבר מטופלות: כותרות `X-Robots-Tag: noindex` ו-`X-Content-Type-Options` מוגדרות
ב-`vercel.json`; נקודת ה-API מקבלת שני סוגי מפתחות בלבד ואינה משמשת כ-KV proxy כללי; תוכניות
מועברות לארכיון ואינן נמחקות, כדי לשמור על היסטוריית הלמידה.

## מודל הנתונים

- **יחידה** → חמישה **נאגטים**. לכל נאגט: פרוסת קריינות, כתוביות, סצנות, שאלת רפלקציה ותרגיל.
- **תוכנית** = לקוח, קהל יעד, רשימת יחידות מסודרת, מסרי פתיחה וסיום, תנאי השלמה וסטטוס.
- **התקדמות** נרשמת ברמת המקטע (נצפה / תורגל / ציון / נקודת עצירה), ומצטברת ליחידה ולתוכנית.

התקדמות מחושבת על יחידות מופקות בלבד. יחידות שעדיין בהפקה מסומנות "בהכנה" ואינן נספרות
במכנה — כדי שהאחוזים ישקפו תוכן שאפשר באמת להשלים. אחוז ההתקדמות בתוכנית משוקלל לפי נאגטים
ולא לפי יחידות, כך שלומד שנמצא בתוך יחידה לא מוצג כאפס.
